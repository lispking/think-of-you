# 验证方法

三层验证，从随时可跑到必须上手。

## 1. 打桩契约测试（主力）

在标准 Lua 里加载 `think-of-you.lua`，用**符合 API 契约的替身**驱动完整流程。
替身不是"能跑就行"：它按设备文档逐项校验参数，越界当场报错。
所以它同时是功能测试和契约测试——能抓住"在电脑上跑得通、到设备上抛异常"的问题。

```sh
lua tests/mock_think.lua
# == 结果: 11853 通过, 0 失败 ==

# 也可以指定要加载的应用文件
lua tests/mock_think.lua think-of-you.lua
```

### 替身校验的契约

| 方面 | 校验内容 |
| --- | --- |
| 绘制 | 矩形不出画布、每帧矩形 ≤128、每帧文字 ≤8 段、单段 ≤63 字节、文字 y ≤224 |
| 网络 | url ≤511 字节且有 scheme、method 合法、headers ≤16 项且 ≤1024 字节、body ≤8192、超时 ≤60000、响应上限 ≤32768 |
| 播报 | 启动阶段禁止调用、正文 ≤512 字节、同一时刻只有一个 |
| 蜂鸣 | 频率 100–5000Hz、时长 20–3000ms |
| 指示灯 | 闪烁时长 10–5000ms |
| 存档 | 键 ≤32 字节、值为有限数字/布尔/≤256 字节字符串、≤32 项、≤1024 字节 |

### 覆盖的行为

启动与首帧、轮询调度、对端播报（含旧版自由文本兼容）、游标推进、脏数据容错、
敲击手势与间隔分辨、连点冷却、发送失败回滚、回显自过滤、
长势与连续天数（含按真实时间回落）、开花、心灯节拍、
合奏（发起方主旋律 / 被叫方伴奏 / 开场时间 / 音符顺序）、
猜拳（三种结果 + 比分存档）、轮询节奏（闲时 10 秒 / 对局 2 秒）、存档恢复与约束。

### 时间是怎么模拟的

- `advance(ms)`：**同时**推进运行时间和墙上时钟，按真实的 20ms 步长跑。
  合奏的开场对齐、心灯节拍、轮询节奏都靠它。
- `jump_wall(sec)`：只把墙上时钟往前跳，不推进运行时间——用来验证长势是**按真实时间**回落，
  而不是按应用跑了多久。

## 2. 用模拟器无界面验证

会发起真实网络请求（真 ntfy、真 JSON），覆盖打桩测不到的部分。

```sh
# 在 SDK 仓库 cargo build 之后
<lingclaw-sdk> --headless think-of-you.lua shot.png

# 专门探真实 API 的脚本
<lingclaw-sdk> --headless tests/real_api_probe.lua /tmp/probe.png
```

无界面模式不创建窗口，Lua 异常时返回非零退出状态；截图反映**执行结束时的画面**，
不会额外等待网络请求完成。

## 3. README 里的截图怎么来的

同样是模拟器渲染，240 × 240，`assets/` 下两张：

```sh
<lingclaw-sdk> --headless <脚本> assets/screen-idle.png
```

为了画面能看，渲染用的是**临时副本**（不进版本库），只改了两处：

- 两张都把 `TOPIC` 换成演示主题，否则状态行会显示"请先设置 TOPIC"；
- 开花那张预置了"已经养了几天"的状态：长势 96、`bloomed = true`、
  连续 3 天、送出 12、收到 9，让画面自洽。

也就是说截图是模拟器按应用自己的绘制代码渲染的，但**状态是喂进去的**，
不是真跑几天攒出来的。

## 4. 真机验证

```sh
./flash.sh              # 推送并逐台回读校验
```

回读能把源码拉回来，本身就证明**应用已经跑起来了**（设备端没有应用在运行时，
`adb pull /miniapp/miniapp.lua` 会失败）。

### 调试时觉得反应慢

正常现象：设备只能主动轮询，**感受到的延迟 ≈ 对方下一次轮询的剩余时间**，
上限就是 `POLL_MS`。三条让它更快的路：

1. **等它自己进密集档**：敲 5 下开一局猜拳、或敲 6 下合奏，期间轮询是 2 秒；
   收到任意一条消息后 15 秒内也会自动进这一档（两端一来一往就都停在 2 秒）。
2. **临时调小 `POLL_MS`**（例如 `3000`），改完两台一起重烧。
   ntfy.sh 公共实例有限速，长期跑别低于 5 秒。
3. **起一个本地中继**：`./ntfy-local.sh`（用 Docker 跑官方 ntfy，限速已放宽）。
   一条命令把两台指过来并重烧：`./ntfy-local.sh --flash`。走 HTTP 没有设备证书问题，
   `POLL_MS` 可以压到 500ms——要真正测"实时感"的玩法只能这么做。

打桩与模拟器都测不到的两件事：

- **按键相关的一切**：敲击手势、猜拳、合奏，只能人工按。
- **两台之间的时钟偏差**：`clock.now()` 只在应用内部可读，主机侧测不到。
  两台设备相差多少秒，只能看它们的指示灯是否一起跳；偏差过大说明某台没校时。
