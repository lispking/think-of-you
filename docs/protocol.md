# 通信协议

两台设备之间没有直连，全部经过公共中继 [ntfy.sh](https://ntfy.sh)。
这份文档说明它们交换什么、怎么认出自己的消息、以及轮询的节奏。

## 前提：只能主动轮询

设备端没有长连接，也没有被动接收能力；HTTP 只有 `http.request` 的 GET 和 POST，
没有 WebSocket。所以收信的唯一办法是**定期主动去拉**。

这也决定了「同时」这件事不能靠消息对齐——延迟以秒计。需要在时间上同步的功能
（心灯、合奏）改用共享的墙上时钟，见[设计取舍](design.md)。

## 收发流程

```
设备 A 敲完 → POST https://ntfy.sh/<TOPIC>            Title 头 = 本条消息的随机 token
设备 B 轮询  → GET  https://ntfy.sh/<TOPIC>/json?poll=1&since=<上次时间戳>
            → 逐行解析 JSON → 按 id 去重 → 按 Title 滤掉自己的回显 → 执行
```

- **POST**：`Content-Type` 不设置，正文就是下面那张表里的消息体。
  响应体只有 1KB 上限，且**只用来判断成败**（`error` 或 4xx/5xx 即视为失败），不解析内容。
- **GET**：`poll=1` 表示取一次就返回；响应体上限放宽到 12KB（平台默认 8KB），
  够装下积压的一批消息。响应是 NDJSON，一行一条消息。

主题名相当于密码：公开实例上任何人订阅同名主题都能看到全部消息。
两台设备必须填**同一个** `TOPIC`，并且它要足够难猜。

## 消息体

消息体是「类型|参数」的短文本，类型是一个小写字母：

| 消息体 | 含义 | 参数 |
| --- | --- | --- |
| `w\|<n>` | 敲了 n 下的短语 | n 是 `WORDS` 的下标（1..4） |
| `m\|<曲>\|<起始秒>` | 邀对方一起奏一段 | 曲目下标、绝对起始秒（UTC） |
| `r\|<动作>` | 猜拳 | 0 = 想开一局；1 石头、2 剪刀、3 布 |

几条边界规则：

- **没有前缀的一律当普通文本念**，所以对面就算还跑着旧版脚本也依然能说话。
  这条兼容路径只在正文不超过 200 字节时生效。
- 整条长度必须在 1..480 字节之间，超出直接丢弃。
- `^[小写字母]|` 这一段是保留前缀空间。给自由文本起首字母 + 竖线的正文会被当成消息类型解析。
- 类型后面必须有参数，`w|` 这种空参数会落回自由文本分支。

`Title` 头不参与上面任何语义，它只用来做自过滤（下一节），也不显示在界面上。

## 自过滤：认「消息」，不认「设备」

ntfy 会把你自己发的那条也回送给你，必须滤掉，否则会自己对自己播报。

做法是：**发送前生成一个随机 token 放进 `Title`**，同时记进一个 16 格的环形缓冲；
收到消息时看 `Title` 是否命中这个缓冲，命中就当作自己的回显丢掉。

- token 是 32 位十六进制随机数，只需要在自己最近发出的 16 条里不重复。
- 环形缓冲 16 格足够覆盖一个轮询周期：发送冷却 1.2 秒、空闲轮询 10 秒，最多也就几条。
- 这里**不设设备身份**。设备端没有任何唯一标识（`app` 只有 `api_version`/`width`/`height`，
  运行环境不开放 `io`/`os`），身份只能靠烧录时注入，那样两台就得各存一份脚本。

**被过滤掉的回显照样要推进游标。** 否则下次轮询会把同一条再拉一遍，永远过滤、永远重来。

## 游标与去重

- `since` 取**上次已处理消息的时间戳 +1**，所以重启或断网后不会重复播报。
- 没有游标时（首次运行、存档丢失）用 `since=1m`，从一分钟前开始拉，兜住刚发生的事。
- 一批消息内用消息 `id` 去重，只需记住最新一条。
- 主题闲置一周以上会清空历史，历史丢了不会影响后续（游标只会往前）。

## 轮询节奏

| 状态 | 间隔 | 常量 |
| --- | --- | --- |
| 空闲 | 10 秒 | `POLL_MS` |
| 对局或合奏进行中 | 2 秒 | `POLL_BUSY_MS` |
| 刚有来往（收到消息后 15 秒内） | 2 秒 | `POLL_BUSY_MS` + `ACTIVE_WINDOW_MS` |

**用户感受到的延迟 ≈ 对方下一次轮询的剩余时间**，上限就是上表里的间隔。
所以一来一往时，收到消息的那一端会进入"还在聊"：两边都停在 2 秒档，
一次来回大约 2 秒；安静 15 秒后各自退回 10 秒档，不白耗公共实例的额度。

进入对局、合奏，或刚收到消息的那一刻，都会把下一次轮询**提前**（`hurry_poll()`），
不等满当前周期，否则回合制会慢半拍。

应用自己保证同一时刻最多一个在途 GET 和一个在途 POST：
`polling`/`uploading` 为真时不再发起新的同类请求（平台上限是 4 个并发请求）。

公共实例有速率限制，`POLL_MS` 不建议低于 5 秒。
